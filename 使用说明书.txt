============================================================================
  员工入职登记网页 · 使用说明书
============================================================================

适用：入职登记网页 1.2（本机版 / 内网版 / 公司服务器版，三套是同一份代码）

一句话：把纸质《员工信息登记表》搬成手机网页——员工扫码填、身份证拍照带出
信息、HR 一键导出可归档的 Word 登记表和能导入摩卡的花名册，纸表填两遍变成
填一遍。

============================================================================
一、这是什么
----------------------------------------------------------------------------

新员工入职要填一张纸质《员工信息登记表 2026.10》，HR 收齐后再把表上信息逐项
敲进摩卡人事系统。纸表既是收集工具，也是入职前那一刻的信息凭证，要留档。

这个网页做两件事：
  1. 员工侧：手机打开链接/扫码，6 步向导填完即提交，身份证拍照自动带出号码；
  2. HR 侧：登录后台按人查看、勾选批量导出，每人一个文件夹（Word 登记表 +
     身份证正反面照片），外面再给一份按摩卡 119 列排好的花名册。

导出只出 Word，不出 PDF——Word 是拿公司模板当母版只往里填字，版式 100% 是
原件；要 PDF 就拿导出的 .docx 用 Word「另存为 PDF」或批量转换工具转一次。

------------------------------------------------------------------------
二、三种用法（同一份代码，三个位置）
----------------------------------------------------------------------------

  本机版    双击「① 双击启动网页版」→ 浏览器自动开 http://127.0.0.1:8080/
            （只有本机能访问，用来自己先跑通看效果）
  内网版    同一台电脑，同一 WiFi 下的手机用 http://192.168.x.x:8080/ 访问
            （给同办公室的人试用；地址会变，见第十节）
  服务器版  把代码放到公司服务器，配好域名和 HTTPS，员工用公网链接访问
            （正式上线，唯一对外的方式）

代码结构（转交他人时先看这里）：
  入职登记小程序/
  ├── ① 双击启动网页版（Mac/Windows）   本地演示启动器，服务器上不需要
  ├── 部署与运维.md                      上线与运维的完整手册（这份说明书的扩展版）
  ├── 网页/                              网站本体（index.html + app.js + 生成器）
  ├── 服务器/                            服务端（server.js 单文件 + backup.js + ocr.js）
  │   └── data/                          ★ 所有数据都在这（records + photos + 账号）
  ├── 备份/                              自动备份产物（zip 快照）
  └── 开发工具/                          测试脚本与旧小程序，服务器上不用传

服务器上只传「网页/」和「服务器/」两个目录，且必须保持这个相对位置
（server.js 写死去上一层「网页/」找页面）。

------------------------------------------------------------------------
三、员工怎么填
----------------------------------------------------------------------------

1. 扫码或点链接，直接进填表页第 1 步（链接末尾带 #form，别删）；
2. 6 步向导填完 51 个字段，红色星号是必填，选填项不填也能过；
3. 身份证拍照：只自动识别 18 位号码，再从号码带出性别和出生日期；
   姓名、民族、住址等汉字一律手填（汉字识别易出错，不做）；
4. 证件照上传、手写签名（签一次，导出 Word 的两处签字栏都会出现）；
5. 提交后得到一个登记编号，还能把整份表摊开核对一遍，写错点「重新填一份」。

几个填写的细节：
  · 学历从高中填起，没读过高中的填初中、小学写在同一行后面；
  · 「工作经历或实习经历」——应届生/首次就业可勾「暂无工作经历」；
  · 「从何渠道得知招聘信息」是必填，选「经人介绍」会再问：内推写姓名，
    中介选沃盛/协和/大赢；
  · 学历证明人及电话、专业等是选填，不填也能提交。

------------------------------------------------------------------------
四、HR 怎么用
----------------------------------------------------------------------------

登录后台（默认账号 HR001，首次启动后务必改密码，见第七节）：

  查看      按人查看完整档案、身份证正反面照片、处理状态与备注
  处理      每条记录标「待核对 / 已入职 / 退回补充」，写备注，按状态筛选
  导出      勾选多人批量导出 → 一个 zip，按人分文件夹 + 一份融合版花名册
  清理      重复提交检测（同名同号/同号不同名会抓出来），一键清理
  发布      生成填写链接 / 二维码 / A4 海报（海报底部写「信息仅用于入职建档」）

导出的花名册按摩卡「导入花名册模板」119 列原样生成，可直接导入；工号、工资
卡号等列入职后由 HR 补。

五、上线要准备什么（问 IT / HR 就按这份）
----------------------------------------------------------------------------

只来得及问四句，先问这四句：服务器能公网访问吗、有没有域名、有没有 HTTPS
证书、Node.js 装没装。

要准备的只有四样（+1 个可选）：

  1. 一台能公网访问的服务器（跑 server.js、存数据）—— 找 IT
  2. Node.js 18 以上 —— 找 IT，或自己装
  3. 一个域名，如 onboard.公司域名.com —— 找 IT / 网管
  4. 443 端口 + HTTPS 证书 —— 找 IT（微信里打开不报警告必须 HTTPS）
  5. Tesseract + 中文包（可选，强烈建议）—— 身份证号码自动识别用，一条命令装完

具体要问 IT / HR 的清单（问完把答案记在部署文档里）：

  服务器
  · 有没有一台公网能打开的服务器？家用手机流量能访问吗？
  · Linux 还是 Windows Server？有没有固定公网 IP？地址多少？
  · 443/80 端口对公网开放吗？前面有没有防火墙/WAF/负载均衡要加白名单？
  · 有没有现成域名/子域名给我用？加解析找谁？
  · HTTPS 证书是公司统一申请续期，还是我自己弄？

  程序怎么放、怎么一直跑
  · 服务器装没装 Node.js？没装能不能自己装 18+？
  · 程序放哪个目录，有没有规定（如 /opt/onboarding）？
  · 要 7×24 一直跑：进程挂了自动拉起、机器重启自启，用 systemd 还是 pm2？
  · 数据目录会不会备份？多久一次，能恢复到哪一天？
  · 单请求/上传大小限制？身份证照片单张约 4MB，一次提交约 10MB。
  · 有没有安全合规要求：统一反向代理、等保、备案？

  审批（问 HR 负责人 / 信息安全）
  · 收集身份证号和照片属敏感个人信息，走哪个审批、谁签字？
  · 没入职的人资料保存多久？到期谁删？
  · 对外提供服务要做什么备案/登记？

  备注（给对方看，不用问）
  · 程序只有一个 server.js，零第三方依赖，不连数据库，数据存服务器本地目录；
  · 需要的能力只有：Node.js + 一个域名 + 443 端口 + 一个能读写的目录；
  · 数据是明文 JSON 和 JPG，备份目录就等于备份全部数据。

六、怎么部署上线
----------------------------------------------------------------------------

完整命令见《部署与运维.md》第四节，这里给主线：

  Linux：
    1) 装 Node（Ubuntu/统信/麒麟）：
       curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
       sudo apt install -y nodejs
    2) 把「网页」「服务器」传到 /opt/onboarding/，结构保持
       /opt/onboarding/网页/…  和  /opt/onboarding/服务器/…
    3) 改 HR 密码（别用默认 HR001/bmai2026）：
       cd /opt/onboarding/服务器 && node server.js --password 你要的密码
    4) 配 HTTPS（Caddy 两行，证书自动续）：
       onboard.公司域名.com { reverse_proxy 127.0.0.1:8080 }
    5) 让它一直跑（关终端不停、重启自启）：
       PUBLIC_URL=https://onboard.公司域名.com TRUST_PROXY=1 \
       SUBMIT_CODE=填写口令 node server.js（再用 pm2 托管）
    （装身份证识别：sudo apt install -y tesseract-ocr tesseract-ocr-chi-sim）

  Windows Server：
    装 Node LTS → 把两个目录放 D:\onboarding\ → 任务计划程序建「开机运行
    node server.js」→ HTTPS 用 IIS 反向代理或 Caddy Windows 版。

上线前必须过一遍（全勾了才对外发）：
  ☐ 用 https:// 打开，地址栏有小锁
  ☐ 已改默认密码 HR001/bmai2026
  ☐ 挂了反代的话 TRUST_PROXY=1 已加（否则登录锁定、限流会失效）
  ☐ 装了 Tesseract + 中文包（可选但强烈建议）
  ☐ 手机用 4G 关 WiFi 实扫一次，能填能提交
  ☐ 提交后 HR 后台能看到这条记录
  ☐ 勾 2 个人导出，zip 是 2 个文件夹 + 1 份融合版花名册
  ☐ 服务器/data/ 已纳入自动备份

服务端参数（启动命令里加）：PORT、HOST、PUBLIC_URL、TRUST_PROXY、
SUBMIT_CODE、SUBMIT_DAILY_MAX、HR_EMP_NO、HR_PASSWORD、AUTO_BACKUP_HOURS、
BACKUP_KEEP、LOG_KEEP_DAYS。一条完整生产启动命令：

  PUBLIC_URL=https://onboard.bmai.com TRUST_PROXY=1 \
  SUBMIT_CODE=公司内部口令 HR_PASSWORD='换成强密码' PORT=8080 node server.js

七、安全与隐私（正式上线前必须看）
----------------------------------------------------------------------------

身份证号 + 照片是《个人信息保护法》里的敏感个人信息，公司层面要定好：
「谁批准收集、保留多久、谁来删」。程序这边已经做了：

  · 身份证号在列表里脱敏（110***********1234）
  · 照片文件名用登记编号，不带姓名；不在静态目录，只能带 token 取
  · 密码 scrypt 加盐哈希存，文件权限 600
  · 同 IP 十分钟最多提交 3 次；全站每天上限 300 份
  · 登录连错 5 次锁 1 分钟（按真实 IP，伪造 X-Forwarded-For 无效）
  · 同一登记编号只允许原设备覆盖，别人改不了
  · 身份证照片只落在服务器临时目录，识别完立刻删，不联外部 OCR 接口

------------------------------------------------------------------------
八、数据与备份
----------------------------------------------------------------------------

唯一原件是「服务器/data/」目录：records/（一人一个 JSON）、photos/（身份证
正反面）、hr.json（账号）、secret.txt（密钥）。网页上看到的列表、导出的
Excel/Word 都从这里读；照片也在这里，不在网页目录下。

备份不用管，服务自己备：启动 20 秒自检，之后每隔 AUTO_BACKUP_HOURS（默认
24 小时）存一份 zip 到「备份/」，只留最近 30 份。要手动备：

  node 服务器/backup.js              # 立即存一份
  node 服务器/backup.js --keep 60    # 改保留份数

⚠️ 关键：备份不能只留在同一台机器。每周把最新 zip 拷一份到网盘或移动硬盘，
否则机器坏了数据跟着一起没。

九、出问题怎么查
----------------------------------------------------------------------------

  现象                          最可能原因 / 怎么办
  手机打不开、一直转圈          用了内网地址或端口没开 → 用 4G 试，让 IT 放行 443
  微信提示「非官方网页」        用的 http → 配 HTTPS 重新生成二维码
  打开是空白页                  网页/ 和 服务器/ 没放同一层 → 核对目录结构
  打开 404 但服务在跑           目录名被改 → 必须叫「网页」，或改 server.js 的 WEB 常量
  上传照片报 413                反代限制请求体 → nginx 加 client_max_body_size 30m
  提示「短时间提交太多次」      触发限流 → 等 10 分钟，或调 SUBMIT_DAILY_MAX
  导出的 Word 变三页            内容撑高表格 → 已自动收紧行距压回两页；还超就删一段经历
  忘记 HR 密码                  服务器上 node server.js --password 新密码
  员工说「提交失败」            要他的 requestId → grep 那串编号 服务器/logs/app-*.log

每天 30 秒巡检：打开 HR 后台看顶部状态条——绿点什么都不用做；黄点/红点点
「详情」看是磁盘、备份还是报错。也可以命令行取：curl -H "x-token: 你的token"
https://你的域名/api/admin/stats。

十、两个容易踩的坑
----------------------------------------------------------------------------

1. 移动文件夹：服务器按启动时的路径找文件。移动后旧路径失效，页面和提交都会
   报错——移完要 Ctrl+C 停掉、到新位置重新启动；移回原位则不用重启。

2. 内网地址会变：DHCP 分配的 192.168.x.x 地址在电脑重启后可能变，同 WiFi 的人
   会打不开。要稳定就找 IT 做「DHCP 地址保留」，或直接用正式域名。

------------------------------------------------------------------------
十一、已知限制（实测出来的，不是推托）
----------------------------------------------------------------------------

  · OCR 在暗光/反光/遮挡下会识别失败——会要求手输，不会给错号；
  · 身份证只识别号码，不识别姓名/民族等汉字（汉字易出错，故意不做）；
  · 数据只存在服务器一台机器上，靠按周备份兜底；
  · 未接公司账号体系，HR 共用一个账号；
  · 花名册里工号、工资卡号等列需入职后由 HR 补；
  · 正式对外必须 HTTPS，否则身份证照片明文过网。
